<objective>
Generalize the single-purpose Version/Ping/Pong DVC plumbing into a generic typed request/response mechanism, and define the owned SDK perception types plus the wire contract that both the Rust deserializer and the C# handlers (Plans 03/04) share. Fully offline, no VM.

This is the FOUNDATION plan: it defines every type, error variant, and wire-schema field name that Plans 02, 03, and 04 build against. Interface-first — contracts here, implementations there.

Purpose: Cash in the two deferred design decisions the envelope was built for (D-4.3 free-form payload; `SensorShared::pending` concurrent correlation) so four new request types reuse one correlation/fulfilment path instead of four hand-written match arms (RESEARCH Patterns 1 and 2).
Output: Generalized `sensor.rs`/`session_loop.rs`, new `perception.rs` (owned types + wire structs + conversions), `Error::SensorRejected` (D-6.4), and offline unit tests for the generalized dispatch.
</objective>

<wire_contract>
This plan is the single source of truth for the Phase 6 wire schema. Plans 03/04 (C#) MUST emit these exact snake_case field names and bare-string enum forms.

Request envelopes (SDK → sensor), all reuse the existing `{version, req_id, type, payload}` shape:
- `WindowList`  — payload: `null`
- `ProcessTree` — payload: `null`
- `SetForegroundWindow` — payload: `{"hwnd": <u64>}`
- `LaunchProcess` — payload: `{"exe": <string>, "args": <string|null>, "cwd": <string|null>}`

Response envelopes (sensor → SDK) echo the SAME `type` and `req_id`, payload = one of:
- success: `{"success": true, "data": <result> }`
- failure: `{"success": false, "error": <string> }`  (D-6.4 semantic failure)

`data` shapes:
- WindowList: array of `{"hwnd":<u64>,"title":<string>,"rect":{"x":<u32>,"y":<u32>,"w":<u32>,"h":<u32>},"z_order":<u32>,"state":"normal"|"minimized"|"maximized","class_name":<string>,"pid":<u32>}`
- ProcessTree: array of `{"pid":<u32>,"parent_pid":<u32>,"name":<string>,"path":<string>,"command_line":<string|null>,"owner":<string|null>}`
- SetForegroundWindow: `null` (success flag alone is the result)
- LaunchProcess: `{"pid":<u32>}`

`rect` is in physical virtual-desktop pixels (framebuffer coordinate space) — a Phase 7 criterion depends on this; the C# side must NOT emit DPI-scaled logical coordinates (per D-6.3 and 06-CONTEXT Implementation notes).
</wire_contract>
