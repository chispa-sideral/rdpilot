The Phase 6 wire schema is defined authoritatively in Plan 06-01's `<wire_contract>` — READ IT FIRST. The C# handler MUST emit exactly those snake_case field names and bare-string enum forms so the Rust `perception::WindowInfoWire` deserializer (06-01) accepts them.

WindowList response `data` is an array of:
`{"hwnd":<u64>,"title":<string>,"rect":{"x":<u32>,"y":<u32>,"w":<u32>,"h":<u32>},"z_order":<u32>,"state":"normal"|"minimized"|"maximized","class_name":<string>,"pid":<u32>}`
wrapped as `{"success":true,"data":[...]}` (or `{"success":false,"error":"..."}` on failure, D-6.4).

Existing conventions (05-01): `[LibraryImport]` only (never attribute `DllImport`), `JsonSerializerIsReflectionEnabledByDefault=false`, every DTO registered in `EnvelopeJsonContext`, NativeAOT does not cross-compile (publish must run on a genuine Windows host). `MsgType` (Envelope.cs) currently has Version/Ping/Pong — this plan adds the new members mirroring the Rust `MsgType` from 06-01.
</interface_context>
