<objective>
Extend the Rust SDK wire/type layer for UIA perception: add `MsgType::Uia`, define the owned public `UiaElement` type plus the crate-internal `UiaElementWire` deserialize-only mirror (with the `control_type_to_role` and `runtime_id_to_string` conversions), and add `Session::get_uia_tree(hwnd)` on the existing Phase 6 round-trip helper. Fully offline — no VM, no C#.

This is the low-risk mechanical Wave-1 plan: it is a pure repetition of the proven Phase 6 `WindowInfo`/`WindowInfoWire`/`get_window_list` pattern (RESEARCH Pattern 1). It runs in parallel with the C# interop scaffolding (07-02, zero file overlap) and defines the wire contract the C# handler (07-04) must produce.

Purpose: Cash in the generic req_id-keyed fulfilment path (established Phase 6) for one more request type, and lock the wire-schema field names + owned-type shape before any handler or live code is written (interface-first).
Output: `MsgType::Uia`, owned `UiaElement` + `UiaElementWire` + conversions in `perception.rs`, `Session::get_uia_tree(hwnd)` in `session.rs`, the `pub use` in `lib.rs`, and offline unit tests for the round-trip (SC#4), the RuntimeId join (D-7.2), and the ControlType map (D-7.3).
</objective>
