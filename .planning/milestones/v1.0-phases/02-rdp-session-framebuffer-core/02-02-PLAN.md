<objective>
Build the live RDP machinery: drive the IronRDP connector to an authenticated active
session over TLS/CredSSP (SESS-01), run an SDK-owned Tokio background task that pumps PDUs
and maintains the latest framebuffer snapshot (SESS-02/CAP-01), keep the session alive with an
automatic zero-delta keepalive (D-06), and expose the `Session` handle with `connect()`,
`screenshot()`, `close()` and a `Drop` guard (D-04/D-07). Leave the `RDPILOT_SENSOR` DVC
registration seam on the connector before `connect_finalize` for Phase 4 (do NOT build the sensor).

Purpose: This is the heart of the phase — the consumer never drives the RDP state machine (D-04);
the SDK owns the loop. Correctness depends on three non-obvious things copied from the upstream
templates: resumption disabled for CredSSP (Pitfall 5), snapshot-on-GraphicsUpdate rather than
sharing the live DecodedImage (Pitfall 3), and DeactivateAll reactivation so a server-side resize
during the idle window doesn't leave screenshots stale/wrong-size (Pitfall 2, threatens criterion #4).

Output: `connect.rs`, `session_loop.rs`, `framebuffer.rs`, `keepalive.rs`, `session.rs` compiling and
re-exported; a `Session` whose public shape matches the user-signed-off API. Live behavior is
proven by the gated integration suite in Plan 03.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SDK → remote RDP server (network) | All RDP traffic crosses TLS on :3389; server cert is the trust decision point |
| remote server → framebuffer | Untrusted graphics PDUs decoded into the DecodedImage; snapshot is the "current perception" integrity point |
| caller → Session lifecycle | connect/close/Drop control the background task + socket |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Spoofing/Tampering | Server-cert trust in `connect.rs` (MITM if validation skipped) | mitigate | Default path uses the validating verifier; `accept_invalid_certs` is risk-named, default off, lab-only (D-15); never silently skip validation |
| T-02-04 | Tampering | TLS downgrade / resumption oracle (CredSSP) | mitigate | `Resumption::disabled()` on the rustls ClientConfig (Pitfall 5, MS-CSSP); rustls negotiates TLS 1.2+ by default |
| T-02-02 | Information Disclosure | Credentials/cert material in logs during connect | mitigate | Never `tracing`-log credential or cert fields (Security V7); credentials are pass-through, SDK never touches OS credential machinery (D-14) |
| T-02-05 | Tampering (integrity of perception) | Stale/wrong-size framebuffer served as "current" after a server resize | mitigate | Snapshot-on-GraphicsUpdate; handle DeactivateAll reactivation to rebuild the DecodedImage (Pattern 5, Pitfall 2) — directly protects criterion #4 |
| T-02-06 | Denial of Service | Keepalive injecting stray input into a focused remote field, or too-infrequent keepalive causing idle disconnect | mitigate | Zero-delta pointer-move null event (never a keystroke); 60s interval < any realistic idle timeout (Pitfall 4); fallback ±1px move documented (A1) |
| T-02-07 | Denial of Service | Background task / socket leak if a Session is dropped without close() | mitigate | `Drop` guard aborts the JoinHandle and closes the channel; OS reaps the TCP socket (D-07) |
</threat_model>
