<objective>
Deliver the keyboard half of input injection: `Session::send_key(KeyAction) -> Result<()>`,
routing `KeyAction::Type(text)` through the per-character Unicode path and `KeyAction::Combo(keys)`
through the scancode down/up path with correct modifier ordering — reusing the pure translation
(`input::key_operations`) and the `Mutex<Database>` + `RdpInputEvent::FastPath` seam already built.

Purpose: INPUT-02 and success criterion #3 (typed text and key combinations like Ctrl+A / Alt+F4
received by the remote app). The translation and scancode table already exist and are unit-tested
offline (Plan 01); this plan is the thin `Session` wiring that applies them through the shared
`Database` and dispatches onto the existing channel — the same shape as `send_mouse`, minus the
coordinate bounds check (keyboard has no coordinates) and minus inter-event timing (a Combo/Type is
a single `apply()` batch; no double-click/drag delay).

Output: `Session::send_key` in `session.rs`, compiling and passing offline `cargo test -p rdpilot`;
live proof (text renders, Ctrl+A selects, Alt+F4 closes) is in Plan 04.
</objective>
