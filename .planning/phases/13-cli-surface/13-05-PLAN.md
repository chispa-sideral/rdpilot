<objective>
Create the `rdpilot-cli` binary crate and deliver CLI-01: the session-lifecycle verbs `connect [--name]` / `list` / `disconnect`, each a thin invoke-and-exit `rdpilot-ipc` client that transparently auto-starts the daemon on first use. This plan also lays the shared CLI infrastructure every later verb reuses — the clap command tree (flat lifecycle/file verbs + grouped `session`/`perceive`/`input`/`file` families, global `--json`), the config-flag layer feeding `rdpilot-config::resolve`, the hand-rolled table renderer, and the `WireErrorCode`→exit-code mapping.

Purpose: CLI-01 is the foundation the operator (and Phase 15's PROOF-02) drives everything else through. The thin-client invariant (D-17) is a hard, `cargo tree`-enforced constraint: the CLI must reach the daemon purely through the relocated `rdpilot-ipc::transport` (Plan 13-01), never by linking `rdpilot`/`rdpilot-daemon`.
Output: A working `rdpilot connect/list/disconnect`, an offline lifecycle integration test driving the REAL daemon binary with the fake connector, and the shared clap/render/exit-code scaffolding for Plans 13-06/13-07.
</objective>
