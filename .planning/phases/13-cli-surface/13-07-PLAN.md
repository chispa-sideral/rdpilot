<scope_decisions>
- **Asymmetric no-clobber (developer decision, research Open Question 1):** `get` (download to LOCAL) enforces no-clobber fully — a `local_path.exists()` check before sending, refused unless `--force`, exit code 8 (offline-verifiable). `put` (upload to REMOTE) accepts `--force` for forward-compatibility but its REMOTE no-clobber is NOT enforced this phase: the CLI/daemon cannot cheaply check remote existence without a new C# sensor round trip (the Phase 10 `FileTransfer` Upload handler has no overwrite-refusal, and the sensor is explicitly out of Phase 13 scope). This is documented as a best-effort/known gap in the `put` `--help` text and the SUMMARY. Do NOT extend the C# sensor in Phase 13.
- **Backlog follow-up:** add a backlog item — "Symmetric remote no-clobber for `put`: extend the C# sensor's FileTransfer Upload handler with a `no_clobber` flag + `File.Exists` check + a live gate" — so the asymmetry is tracked, not silently accepted.
- **Path absolutization uses `std::env::current_dir()` join, NOT `std::path::absolute`:** the workspace pins `rust-version = "1.78"`; `std::path::absolute` stabilized in 1.79 (research Assumptions Log A2). Resolve a relative `local_path` by joining it onto `std::env::current_dir()?` (absolute paths pass through unchanged).
</scope_decisions>
