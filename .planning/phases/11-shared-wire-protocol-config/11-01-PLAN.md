<objective>
Create the `rdpilot-ipc` workspace crate: the daemon-to-client wire protocol as pure serde DTOs with zero dependency on `rdpilot` (or IronRDP). It defines session identity as a required, non-optional schema field on every request verb, a credential-free response set, the D-28 wire error taxonomy (types only), and an owned `TransferOutcome` mirror of the Phase 10 file-transfer result.

Purpose: Both BLOCKING Phase 11 criteria live here — SESSION-02 (a missing `session` is a hard deserialize rejection, not a fallback) and CONFIG-03 (no wire response type can carry a secret, by construction). Keeping the crate free of `rdpilot`/IronRDP preserves the thin-client premise (D-17): Phase 13/14 client binaries link this crate without pulling in the RDP stack.

Output: A buildable, tested `crates/rdpilot-ipc/` crate added as a workspace member, exporting `SessionId`, `Request`, `SessionScoped`, `WireResponse`, `SessionStatus`, `SessionLifecycle`, `WireError`, `WireErrorCode`, `TransferOutcome`.
</objective>

<scope_decisions>
Binding resolved decisions from the phase discussion (override the research's open questions):

- **Decision 1 (crate is dependency-free of `rdpilot`):** `rdpilot-ipc` MUST NOT depend on `rdpilot`. Define the `WireError`/`WireErrorCode` TYPES here, but NOT the `From<rdpilot::Error>` conversion — that conversion moves to the Phase 12 daemon crate (which already depends on `rdpilot`). Verify with `cargo tree` (Task 1) that neither `rdpilot` nor `ironrdp*` appears in this crate's dependency graph.
- **Decision 3 (catch-all error code):** `WireErrorCode` carries the five fixed D-28 codes PLUS a single `Internal` catch-all variant (kebab-case `internal`) documented as the fallback for the ~9 SDK `Error` variants outside D-28's fixed set. Phase 11 only needs the enum to CONTAIN the catch-all; the actual mapping is Phase 12.

Wire verb scope for THIS phase (assumption — flagged for review): the `Request` enum ships the file-transfer verbs (`Put`/`Get`, mandatory per the Phase 10 dependency) plus the primitive-field operational verbs (`Ping`, `Screenshot`, `LaunchProcess`, `SetForeground`). The rich input/perception verbs (mouse/key/UIA/world_state/window+process list) are deferred to Phases 13/14, because their exact wire shape is coupled to the Anthropic computer-use action schema (D-21, Phase 14) and CLI flag design (Phase 13) — decisions explicitly out of Phase 11's boundary. The `SessionScoped` exhaustive-match trait is the structural forcing function that makes any future verb added without a `session` field a compile error.
</scope_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → daemon (wire) | Untrusted JSON request crosses into the daemon; deserialize is the first gate (Phase 12 wires the transport; Phase 11 defines the type that gates) |
| daemon → client (wire) | Response DTOs serialized back to the client — must never carry rdpilot's own connect credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Elevation of Privilege / Tampering | `Request.session` field | high | mitigate | Non-`Option`, no `#[serde(default)]` session field on every variant → a missing field is a hard `serde_json::Error`, never an implicit default target (SESSION-02 test, Task 2) |
| T-11-02 | Information Disclosure | `WireResponse` DTOs | high | mitigate | Structural credential separation (D-31): no password field on any response type; `rdpilot-ipc` does not depend on `rdpilot-config`, so `Credentials` cannot enter the wire graph (CONFIG-03 sentinel test, Task 3) |
| T-11-03 | Denial of Service | `Request` deserialize | medium | mitigate | serde's `#[serde(tag="op")]` unknown-variant handling returns a typed `Err`, never a panic; `#![deny(clippy::unwrap_used/expect_used)]` on the crate forbids panicking parse code |
| T-11-04 | Tampering / Information Disclosure | `SessionId` empty-string bypass | medium | mitigate | `SessionId` custom `Deserialize` rejects `""`, closing the "field present but empty" loophole around the required-field guarantee (Task 1) |
| T-11-SC | Tampering | cargo dependency installs (serde, serde_json, thiserror) | low | accept | All three are long-established, already workspace dependencies; RESEARCH Package Legitimacy Audit resolved every package `[OK]` via slopcheck; no `[ASSUMED]`/`[SUS]` packages introduced |
</threat_model>
