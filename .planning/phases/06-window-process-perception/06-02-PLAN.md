<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → Session methods | `hwnd`/`exe`/`args`/`cwd` are caller-supplied; `launch_process` is an intentional remote-code-execution primitive within the already-authenticated RDP session |
| sensor reply → owned type deserialization | Untrusted `data` JSON is deserialized into owned types via serde wire structs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-02 | Denial of Service | reply payload deserialization | medium | mitigate | `serde_json::from_value` into wire structs returns a typed `Err` (mapped to `Error::Dvc`) on malformed/oversized `data`; never `unwrap` a field, never panic (API-01, ASVS V5) |
| T-06-03 | Elevation of Privilege | `launch_process` | medium | accept | Arbitrary remote process launch is PROC-01's intended capability; the RDP session's own NLA/CredSSP authentication is the sole and sufficient trust boundary (RESEARCH Security Domain V4) — no additional gate is introduced, documented as accepted-by-design |
| T-06-05 | Denial of Service | pending-map leak on timeout | low | mitigate | Every method removes its pending entry on timeout (mirrors `ping()`) so a stale late reply cannot resurrect or double-fulfil it |
</threat_model>
