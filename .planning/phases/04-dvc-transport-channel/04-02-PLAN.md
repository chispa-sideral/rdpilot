<objective>
Wire the Plan-01 processor into the live connect path and build the outbound ping request/response
path. Register `RdpilotSensorProcessor` on `DrdynvcClient` before `connect_begin` (satisfying SC#1's
registration-before-connect constraint), thread one `Arc<SensorShared>` clone out of `connect()` onto
the `Session`, add the `RdpInputEvent::Ping(u64)` session-loop arm that proactively encodes a ping via
`ActiveStage::encode_dvc_messages` (the `encode_resize` precedent — RESEARCH Q1), and implement
`Session::ping() -> Result<Duration>` with handshake fast-fail and a 500 ms timeout.

Purpose: This is the SC#1 + SC#2 mechanism. `DvcProcessor::process()`/`start()` are reactive only — a
proactive ping MUST originate from the session loop that owns the mutable `ActiveStage` (RESEARCH Q1,
verified against `ActiveStage::encode_resize`). The `req_id`-keyed `oneshot` map crosses the dedicated
session-loop OS-thread boundary cleanly (`oneshot` is runtime-agnostic). Everything here is
offline-buildable and offline-unit-testable up to the point of an actual network round-trip; the live
proof is Plan 03.

Output: `connect.rs` registration + return-tuple change, `session_loop.rs` Ping arm + variant,
`session.rs` `ping()` + fields. `cargo build`/`cargo test -p rdpilot` green offline; existing Phase 2/3
tests unaffected.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → Session::ping() | Public async entry; must never panic and must never leak an ironrdp type (D-09, API-01) |
| session-loop thread ↔ caller thread | The `oneshot`/`pending` map crosses the dedicated session-loop OS-thread boundary; correctness of the cross-thread handoff is the integrity point |
| SDK → RDP server (RDPILOT_SENSOR) | Outbound ping bytes ride the existing RDP TLS tunnel (Phase 2); no new crypto/transport surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03 | Denial of Service | A ping with no responder hangs `Session::ping()` forever | high | mitigate | `tokio::time::timeout(500ms)` bounds every round trip; timeout removes the leaked `pending` entry and returns `Error::Dvc` (SC#2) — unit-tested |
| T-04-04 | Tampering | Silent version-skew: a mismatched channel still used for pings | high | mitigate | `ping()` reads `HandshakeState` first and returns `Error::Dvc` without sending when `Mismatched` (SC#3, RESEARCH A1) — unit-tested |
| T-04-05 | Tampering | Borrow-order bug mixing `get_dvc` + `encode_dvc_messages` (Pitfall 3) yields wrong bytes or fails to compile | medium | mitigate | Block-scoped borrow extracts owned `(channel_id, Vec<DvcMessage>)` before the second `&mut` call, mirroring `encode_resize`; compile + grep guard against hand-rolled PDU chunking |
| T-04-SC | Tampering | cargo dependency supply chain | low | accept | No new crates this plan (RESEARCH Package Legitimacy Audit); serde promotion already done in Plan 01 |
