<objective>
Prove the DVC channel end-to-end against the live Phase 1 target (D-4.1 — local loopback rejected).
Author the throwaway PowerShell responder (server-side `RDPILOT_SENSOR` via `WTSVirtualChannelOpenEx`
P/Invoke, Version echo, Ping→Pong), a WinRM deploy helper that launches it inside the interactive RDP
session, and a gated `sensor_ping_pong_under_500ms` test that connects, lets the handshake settle, and
asserts a `Session::ping()` round-trip under 500 ms (SC#2). The handshake being a hard precondition of
a successful ping is the live proof of SC#3's positive path (version handshake first). Default offline
`cargo test` stays green.

Purpose: This is the phase Nyquist gate. SC#2 and SC#3-positive are only meaningfully provable against
a real RDP target (D-4.1). The SC#3 NEGATIVE path (version mismatch) is unit-covered in Plan 01 and is
NOT live-constructible in-phase (both handshake sides are authored together — RESEARCH A3); do not
attempt a live mismatch. The single genuine live-integration risk is session targeting: the responder's
`WTSVirtualChannelOpenEx(WTS_CURRENT_SESSION, ...)` must execute inside the interactive RDP session the
SDK creates, not WinRM's Session 0 — this is surfaced explicitly for empirical resolution at the live
run (mirroring how Phase 3 tuned double-click/drag empirically).

Output: `tests/fixtures/sensor-responder.ps1` (throwaway), `tests/fixtures/deploy-responder.ps1`,
`tests/live_session.rs::sensor_ping_pong_under_500ms`. Offline `cargo test -p rdpilot` green; the live
ping/pong pass is the end-of-phase human-check.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| deploy-responder.ps1 → live VM (WinRM) | Credentials from `.secrets/connection.json` cross to the target over WinRM; must never be printed/logged (threat T-02 family, Phase 1/2 convention) |
| responder ↔ SDK over RDPILOT_SENSOR | The DVC channel is unauthenticated by design (Pitfall m3); any same-session process could open it — accepted for the single-tenant throwaway lab VM |
