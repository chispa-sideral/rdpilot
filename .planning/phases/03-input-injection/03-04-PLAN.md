<objective>
Prove Phase 3 works end-to-end against the live Phase 1 target. Add a screenshot-diff helper
(assert a meaningful region changed) extending Phase 2's frame helpers, then gated (#[ignore],
RDPILOT_LIVE) integration tests covering all four success criteria: a menu-activating click (SC#1),
every mouse action type (SC#2), typed text + key combos (SC#3), and the enforced coordinate contract
(SC#4). Finish with a blocking human-verify checkpoint that runs the canonical validation against a
freshly provisioned VM and empirically confirms the double-click delay and drag step-count.

Purpose: This is the Nyquist phase-gate. SC#1/#2/#3 are only meaningfully provable against a real
Windows RDP target via screenshot-diff (D-3.4 — there is no ack path; the framebuffer is the only
observable). The double-click 100ms gap (D-3.7) and drag ~5-step count (D-3.8) are LIVE-VERIFY items
per RESEARCH §4 — validated empirically here, not assumed. Because process-launch is a Phase 6
capability, targets are app-independent, standard-integrity, reversible OS surfaces (desktop context
menu, Start menu via Ctrl+Esc, Start search typing, the Alt+F4 shutdown dialog) — NOT a launched app,
and never an elevated target (Pitfall 4 / C4 UIPI).

Output: a screenshot-diff helper + gated input tests in `tests/live_session.rs`, default offline
`cargo test` still green, and a recorded canonical-run pass that gates `/gsd-verify-work`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test → .secrets/connection.json | Live credentials enter test code from the gitignored secrets file (reused Phase 2 harness) |
| test → remote RDP server | Authenticated TLS session injecting real input into the live Phase 1 VM |
| injected input → remote OS surface | Input drives real OS surfaces (Start menu, shutdown dialog) — must be reversible and standard-integrity |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12 | Denial of Service | Input silently swallowed by UIPI on an elevated target (Pitfall 4 / C4) | medium | mitigate | Scope every live target to standard-integrity OS surfaces (desktop/Start/shutdown dialog); documented checkpoint constraint (no code fix exists in this SDK's boundary) |
| T-03-13 | Tampering (test integrity) | Live input tests silently passing as no-ops when the target is absent | medium | mitigate | `#[ignore]` + None-early-return; the canonical run sets RDPILOT_LIVE=1 --include-ignored and the checkpoint asserts passed (not skipped) |
| T-03-14 | Information Disclosure | Typed test strings leaking into test logs | low | mitigate | Assert typed text only via screenshot-diff; never print the string (Security V5) |
| T-03-15 | Denial of Service (irreversible side effect) | Alt+F4 closing a needed window or the shutdown dialog actually shutting down the VM | medium | mitigate | Alt+F4 targets the desktop shutdown DIALOG and is immediately cancelled with Esc; the VM is left untouched; Phase 1 auto-destroy is the backstop |
| T-03-16 | Denial of Service (cost) | Live VM left running after the canonical run | low | mitigate | Checkpoint instructs `infra/manage-env.ps1 down`; Phase 1 scheduled auto-destroy (ENV-03) is the backstop |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages introduced (RESEARCH Package Legitimacy Audit — no Cargo.toml change) |
</threat_model>
