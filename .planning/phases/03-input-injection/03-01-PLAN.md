<objective>
Build the offline contract layer for input injection: the owned public vocabulary
(`MouseAction`, `KeyAction`, `Button`, `Key`), the hand-written IBM PC/AT Scan Code Set 1
table (`Key` -> `ironrdp_input::Scancode`), the pure translation from those owned types into
ordered `ironrdp_input::Operation` batches, and the `Error::CoordinateOutOfBounds` variant.
This is the interface every later plan consumes — no `Session`, no channel, no VM touched here.

Purpose: Interface-first ordering. Plans 02 (mouse) and 03 (keyboard) become thin `Session`
wiring because ALL the fiddly, source-verified translation logic — the Pitfall 5
MouseMove-before-WheelRotations rule, the Pitfall 1 |dy|>255 split, the D-3.5 modifier ordering,
and the scancode table — lives here as pure functions with exhaustive offline unit tests. No
hand-built `FastPathInputEvent`/`KeyboardFlags` (that avoids the two-`KeyboardFlags` collision,
Pitfall 2); everything routes through `ironrdp_input::Operation` and later `Database::apply`.

Output: `crates/rdpilot/src/input.rs` (new), `Error::CoordinateOutOfBounds` in `error.rs`, and the
`pub use` in `lib.rs`. Compiles and passes offline `cargo test -p rdpilot` with no VM.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → owned input vocabulary | Untrusted (x,y,dy,text,keys) enter the SDK as owned enums; validation/translation is the integrity point |
| translation → ironrdp-input/ironrdp-pdu | Constructed Operations are the pre-wire representation; a wrong scancode or wrapped wheel magnitude is silent data corruption |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | Wheel-rotation magnitude silently truncated by MousePdu::encode's `as u8` (Pitfall 1) | high | mitigate | Scroll translation splits any |dy|>255 into in-range WheelRotations before it reaches encode; unit-tested |
| T-03-02 | Tampering | Wrong `KeyboardFlags` type (8-bit vs 16-bit collision, Pitfall 2) producing malformed key PDUs | medium | mitigate | All keyboard construction routes through `ironrdp_input::Operation`; no hand-built KeyboardEvent (grep-guarded) |
| T-03-03 | Tampering | Scroll applied at a stale mouse position because WheelRotations carries no x/y (Pitfall 5) | medium | mitigate | Scroll batch always emits MouseMove(x,y) before WheelRotations; unit-tested |
| T-03-04 | Denial of Service | Panic on a degenerate Combo (empty / all-modifier / modifier-free) reaching a slice index | low | mitigate | key_operations handles all partitions without indexing panics (API-01); unit-covered |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages introduced (RESEARCH Package Legitimacy Audit: ironrdp-input/ironrdp-pdu already vetted, pinned in Cargo.lock; no Cargo.toml change) |
</threat_model>
