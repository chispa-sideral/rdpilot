<objective>
Wire input injection into the SDK-owned session and deliver the full mouse surface. Add the
`RdpInputEvent::FastPath(Vec<FastPathInputEvent>)` variant + select! arm the Phase-2 loop already
predicted; give `Session` a `Mutex<ironrdp_input::Database>` and a connect-time `desktop_size`,
expose `Session::desktop_size()`, enforce the coordinate contract in `send_mouse` (reject out-of-bounds
with `Error::CoordinateOutOfBounds` before any PDU), and implement `send_mouse` for move / click
(L/R/M) / double-click / scroll / drag — with all inter-event timing on the caller's context.

Purpose: This is the load-bearing architectural plan. The `Database` MUST live in `Session`
(Mutex-guarded, locked only for the synchronous `apply()`, never held across `.await`), NOT in the
session_loop — the double-click/drag delays are `tokio::time::sleep` on the caller's runtime, because
sleeping inside the loop's `select!` would starve PDU reads and jitter the keepalive (Pitfall 3, the
single most important non-obvious constraint this phase carries). The bounds check is what makes
SC#4 "enforced", not merely documented.

Output: `session_loop.rs` gains the FastPath variant + arm; `session.rs` gains the fields, the
`desktop_size()` accessor, a private bounds check, and `send_mouse`. Compiles and passes offline
`cargo test -p rdpilot`; live behavior is proven by Plan 04.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → Session::send_mouse | Untrusted coordinates enter here; the bounds check is the enforcement point (SC#4) |
| Session → session_loop (mpsc) | Pre-built FastPathInputEvent batches cross the channel to the dedicated loop thread; the loop only forwards, never constructs |
| Session ↔ Mutex<Database> | Shared mutable input state; correctness depends on the guard never crossing an .await |
