<objective>
Add the ONE genuinely new SDK+sensor capability the phase needs: a scoped, caller-configurable deeper UIA walk. The 09-01 live spike proved 7-Zip File Manager's meaningful UI (File/Edit/View menu items, the Add/Extract/Test/Copy/Move/Delete/Info toolbar buttons, and the listview rows) sits ONE level below `get_uia_tree`'s `TreeScope_Children`-only scope (D-7.4), which returned just 5 depth-1 container elements (Window/ToolBar/Pane/TitleBar/MenuBar). This plan adds a bounded deeper walk across the Rust SDK, the wire request, and the C# sensor handler — the human-approved, flagged scoped addition (D-9.1) that re-assesses D-7.4, so the harness (09-03) can assert real deeper elements and pick a real SC#3 navigation target.

Purpose: Turn the recorded 09-01 gap into a real capability WITHOUT redesigning the UIA subsystem — reuse the existing `FindAll(TreeScope.Children)` building block level-by-level up to a bounded depth, keep the wire/owned-type discipline (D-09), and keep the walk depth-capped so it stays within the Phase 7 SC#3 500ms sensor-side budget (live-tuned in 09-04).
Output: `perception.rs` (owned `UiaScope`), `lib.rs` (re-export), `session.rs` (`get_uia_tree(hwnd, scope)` + `max_depth` wire field + migrated `world_state` internal calls), `tests/live_session.rs` (existing get_uia_tree callers migrated to the new signature — NOT the proof test), `sensor/UiaTree.cs` + `sensor/Program.cs` (the depth-bounded walk). All offline-verifiable (compile + unit + AOT-trim); the live behavioral proof is the 09-04 gate against a freshly AOT-rebuilt sensor.
</objective>
