**Gathered:** 2026-07-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Make `rdpilot` available in this box for other agents so we can dogfood it — author a `SKILL.md` documenting the `rdpilot` CLI (commands, connection setup, common workflows) and install the CLI (and its required companion daemon) so other agents on this machine can discover and invoke it.

</domain>

<decisions>
## Implementation Decisions

### Skill location
- **D-1:** SKILL.md is authored in the repo at `.claude/skills/rdpilot/SKILL.md` (version-controlled); the install step copies or symlinks it into BOTH `~/.claude/skills/rdpilot/SKILL.md` (for Claude Code agents) AND `~/.agents/` (mirrored there too, for non-Claude agents) so every agent on this machine — Claude or otherwise — discovers it. Repo is source of truth; both global locations are discovery surfaces.

### Install scope
- **D-2:** Provide a repeatable install script (or justfile target) that builds AND installs BOTH binaries — `rdpilot` (crate rdpilot-cli) and `rdpilot-daemon` — to `~/.cargo/bin` (the daemon MUST be on PATH because the CLI auto-starts it via connect_or_spawn). The script also seeds a gitignored `~/.config/rdpilot/config.toml` skeleton and installs the SKILL.md to BOTH global skill locations — `~/.claude/skills/rdpilot/` AND `~/.agents/` — per D-1. `cargo install --path crates/rdpilot-cli` alone is insufficient (installs CLI only).

### SKILL.md depth
- **D-3:** Document the FULL CLI verb surface (connect / list / disconnect + perception / input / launch / put / get), but quickstart-first: lead with a quickstart + common read/inspect agent workflows, then a compact per-verb reference. Not an exhaustive per-flag reference.

### Dogfood target & credentials
- **D-4:** Placeholder-only. SKILL.md documents the config schema (config.toml fields), the `RDPILOT_*` env vars, and CLI flags, and the layering (file → env → flag). The seeded config.toml skeleton (D-2) contains PLACEHOLDER values only — no real credentials are committed or seeded, and there is NO direct wiring to the Azure live-test infra (999.3). Each agent supplies its own target host + credentials. SKILL.md must include read/inspect-only safety guidance for agents driving a real RDP target.

### Claude's Discretion
- Exact install script mechanism (shell script vs justfile target) and its precise location in the repo.
- Exact SKILL.md structure/section ordering within the quickstart-first constraint (D-3).
- Exact wording of the read/inspect-only safety guidance (D-4).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- CLI builds natively on this Linux host: `cargo build --release -p rdpilot-cli` → `target/release/rdpilot` (no Windows cross-build needed for the client; the daemon holds the RDP session).
- Existing install path today: `cargo install --path crates/rdpilot-cli` (CLI only) — the D-2 script must additionally build/install `rdpilot-daemon`.

### Established Patterns
- Daemon IPC on Linux: `$XDG_RUNTIME_DIR/rdpilot/daemon.sock` (mode 0700); CLI auto-starts the daemon on first connect (connect_or_spawn); daemon self-shuts-down when the registry empties.
- Config fields: host, port, username, password, domain, accept_invalid_certs, share_root, sensor_binary_path. share_root default: `$XDG_DATA_HOME/rdpilot/transfer-staging`.

### Integration Points
- Greenfield for the skill: no `.claude/skills/` directory exists in the repo yet, and no SKILL.md exists anywhere — this phase creates both.

</code_context>
