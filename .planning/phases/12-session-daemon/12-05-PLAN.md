<objective>
Implement the crash-survivable reconciliation layer (DAEMON-04, Pitfall 9): a minimal disk-persisted JSON record per session written on connect and removed on clean disconnect/reap, a startup scan that loads any leftover records (the daemon died before cleaning them up) and seeds them into the registry as `Orphaned` entries, so a possibly-still-live remote Windows session is SURFACED for explicit reconciliation — never silently forgotten and never blindly auto-killed (D-19/D-31). Prove the full crash→restart→surface loop OFFLINE.

Purpose: The in-memory registry (locked D-19) has no record surviving a `kill -9` unless something is written to disk BEFORE the crash. This plan is that something. The offline BLOCKING portion — write a record, simulate a crash (drop without clean removal), re-scan at startup, assert the session reappears as `Orphaned` in `list` — carries the bulk of DAEMON-04's automated coverage. The remaining live-only claim (that the remote Windows session is genuinely still live server-side rather than logged off) is confirmed against a real VM in Plan 07.

Output: `reconcile.rs` (the JSON `ReconciliationSink` + `scan_orphans`) and the offline `crash_restart_reconcile.rs` test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon process crash → restart | State that must survive a `kill -9` lives only on local disk; nothing else carries it |
| reconciliation file → daemon startup | A possibly-corrupt/attacker-touched state file is read at startup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-14 | Repudiation / DoS | Orphaned remote session silently forgotten across crash cycles (zombie leak) | high | mitigate | Disk record written on connect, removed only on clean close; startup scan seeds leftovers as Orphaned; test asserts non-empty list after restart |
| T-12-15 | Tampering | Torn reconciliation file from a crash mid-write | medium | mitigate | Atomic temp-write + `rename`; a crash leaves old-or-new complete file, never partial |

| T-12-17 | Destruction of work | Blindly auto-killing a possibly-live remote session on restart (D-31 violation) | high | mitigate | Orphans are SURFACED as `Orphaned`, reconciled only via an explicit `close` call — no auto-teardown on startup |
