<objective>
Extend the shared `rdpilot-ipc` wire crate and the Phase 12 daemon with the two upstream primitives the MCP surface needs before its tool handlers can exist: (1) a `DesktopSize` request/response verb pair so the coordinate bridge (`scale_to_native`, Plan 14-03) can source a session's REAL native desktop dimensions instead of PNG-header-sniffing (research Open Question 1, recommendation adopted); (2) a single canonical `parse_wire_key` key-name parser promoted into `rdpilot-ipc` so the MCP `computer` tool's `key`/`hold_key` actions and the CLI share ONE 67-entry table rather than a drifting second copy (research Don't Hand-Roll).

Purpose: MCP-04's bridge is only correct if it scales against the actual negotiated desktop size; sourcing that over the wire (not by decoding screenshot pixels) removes a call-ordering coupling and a PNG-parsing dependency. Promoting the key parser keeps the future MCP crate a thin `rdpilot-ipc` client (no third key table) and preserves this codebase's exhaustive-match/no-drift culture.
Output: `Request::DesktopSize`/`WireResponse::DesktopSize`; `rdpilot_ipc::parse_wire_key`; a `ManagedSession::desktop_size` seam method + real forward + daemon dispatch arm.
</objective>
