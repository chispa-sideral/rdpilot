<objective>
Scaffold the `rdpilot-mcp` crate as the fourth thin `rdpilot-ipc`/`rdpilot-config`-only client of the daemon (D-17): a workspace member with the pinned `rmcp` 2.2.0 + `schemars` ^1.0 dependency set, an rmcp stdio server bootstrap (MCP-01), the per-call one-shot daemon transport relocated from the CLI's `connect.rs` pattern and wrapped in an explicit per-verb-class `tokio::time::timeout` (MCP-06's Layer-3 mechanism), the per-verb-class timeout constants, and the crate's error taxonomy (`McpError`) that renders `WireError { code, message }` as an rmcp tool error (D-28) and adds a client-local `Timeout` class.

Purpose: establishes the transport + concurrency + error spine every tool handler in Plans 14-03/14-04 builds on, and locks the thin-client invariant at the manifest level before any tool code is written. rmcp already spawns a task per inbound request (isolation Layer 1) and the daemon isolates per-session (Layer 2); this plan supplies the one piece those two do not — the explicit bounded timeout so a hung round-trip never parks the calling agent's loop indefinitely.
Output: a compiling, startable MCP server with zero tools yet; `round_trip_bounded`; `timeouts` constants; `McpError`.
</objective>
