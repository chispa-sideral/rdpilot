<objective>
Expose the eleven `rdpilot_`-prefixed native MCP tools (D-14.2 namespace) that mirror the daemon's non-computer verb set: `rdpilot_world_state`, `rdpilot_uia`, `rdpilot_window_list`, `rdpilot_process_list`, `rdpilot_launch`, `rdpilot_foreground`, `rdpilot_connect`, `rdpilot_list`, `rdpilot_disconnect`, `rdpilot_put`, `rdpilot_get` (MCP-03). File put/get return `{path, bytes_transferred, checksum}` METADATA ONLY and can NEVER inline file bytes (MCP-05/D-22) — a property already structurally true of `WireResponse::Transfer(TransferOutcome)`, enforced here at the type level and asserted by a planted-bytes test. `rdpilot_connect` resolves connection details through `rdpilot_config::resolve` with an MCP-init override layer whose keys reuse the D-27 vocabulary verbatim. Document the file-transfer trust model plainly (developer decision: NO server-side local-path sandbox — the MCP host governs tool approval + sandboxing, local paths behave as the CLI's trusted-operator model). Prove MCP-01 with a tools/list schema test covering all twelve tools (computer + 11 native).

Purpose: completes the dual tool surface. MCP-05 is satisfied by composition (the Transfer DTO has no byte field), so the work is passthrough + a regression guard, NOT new stripping logic. Every tool carries a required `session` (D-29).
Output: the 11 native tools; the MCP-init config-param layer; the README trust-model doc; the tools/list schema test.
</objective>
